1. Đọc file liên quan.
2. Phân tích nguyên nhân hoặc mục tiêu.
3. Liệt kê file dự kiến thay đổi.
4. Lập plan ngắn gọn.
5. Chỉ implement trong phạm vi task.

Sau khi sửa code:
1. Chạy verification phù hợp: lint, typecheck, test, build, hoặc audit script nếu có.
2. Review git diff.
3. Báo cáo file đã sửa, command đã chạy, kết quả, rủi ro còn lại.

## Web Quality baseline

Mọi thay đổi frontend/web production phải cân nhắc: Performance, Core Web Vitals, Accessibility/WCAG 2.2, SEO, Security/Best Practices.

Ngưỡng mục tiêu:
- LCP ≤ 2.5s
- INP ≤ 200ms
- CLS ≤ 0.1
- TTFB < 800ms nếu có thể
- WCAG AA cho nội dung quan trọng
- Không tạo mixed content, console error, invalid HTML nghiêm trọng

Chi tiết đầy đủ và checklist theo từng chủ đề nằm trong các rule import bên dưới; dùng skill `/web-quality-audit`, `/performance-review`, `/core-web-vitals-review`, `/accessibility-review`, `/seo-review`, `/best-practices-review` khi cần audit sâu.

## Tổng quan dự án

Ứng dụng ecommerce fullstack: NestJS API (`apps/api`) + Prisma/MariaDB, frontend Next.js 15 App Router (`apps/web`), được tổ chức qua npm workspaces và Docker Compose. Workflow phát triển chính là dùng Docker (xem README.md), không phải `npm run dev` chạy local.

## Lệnh (Commands)

Chạy từ thư mục gốc repo (npm workspaces):

```bash
npm run dev            # chạy đồng thời dev server của api và web
npm run build          # build api rồi build web
npm run lint           # lint api rồi lint web
npm run prisma:generate
```

Theo từng app (chạy trong `apps/api` hoặc `apps/web`):

```bash
# apps/api
nest start --watch     # npm run dev
eslint "src/**/*.ts"   # npm run lint
prisma generate        # npm run prisma:generate

# apps/web
next dev -p 3000       # npm run dev
next lint               # npm run lint
prettier --write "src/**/*.{ts,tsx}"   # npm run format
```

Không có test runner nào được cấu hình ở cả hai app — không có script unit/e2e test.

### Docker (workflow chính)

```powershell
docker compose up -d --build          # khởi động db, api, web
docker compose logs -f api            # hoặc web / db
docker compose down                   # dừng, giữ lại db volume
docker compose down -v                # dừng và XÓA db volume (mang tính phá hủy)
```

Lần chạy đầu tiên sẽ tự động tạo database `core` và import `scripts/dump-core.sql` (chỉ khi bảng `product` chưa tồn tại) cùng với `database/init/02-admin-dev.sql` và các file trong `database/migrations/`. Port: web `3009`, api `3010` (container lắng nghe ở `3001`), db `3307` → `3306`. Nếu sau khi rebuild mà sản phẩm bị trống, chạy `scripts/check-db.sh` rồi `scripts/restore-db.sh`.

Admin UI: `http://localhost:3009/admin`, tài khoản đăng nhập seed local là `demo` / `Admin@123`. Swagger: `http://localhost:3010/docs`.

## Kiến trúc (Architecture)

### Backend (`apps/api`, NestJS + Prisma + MariaDB)

Phân lớp nghiêm ngặt cho từng module — **controller và service tuyệt đối không được inject `PrismaService` trực tiếp**:

```
controller -> service -> repository -> Prisma
repository -> projector -> public response shape   (khi cần mapping)
```

Quy ước cấu trúc module (`src/modules/<module>/`):
```
<module>.module.ts
<module>.controller.ts
<module>.service.ts
<module>.repo.ts        # lớp duy nhất được phép chạm vào Prisma
<module>.projector.ts    # tùy chọn: hàm mapping thuần cho các Prisma row phức tạp
dto/*.dto.ts             # DTO class-validator/class-transformer cho mọi request body/query
```

Các module hiện có: `auth`, `catalog`, `checkout`, `content`, `admin` (xem `apps/api/src/modules/`).

Các quy ước chính:
- Controller trả về `ok(data, meta?)` từ `src/common/api-response.ts`; service không bao giờ tự bọc response.
- Các route admin được bảo vệ dùng `JwtAuthGuard` + `AdminRoleGuard` (`src/modules/auth/guards/`).
- Repository throw Nest HTTP exception cho các lỗi liên quan DB; không catch/rethrow lỗi Prisma chỉ để log.
- Projector chuyển `Decimal` → number/string và `BigInt` → string, đồng thời loại bỏ các field nhạy cảm (ví dụ password); không gọi DB hay chứa business logic ở đây.
- Global API prefix là `/api` (thiết lập trong `main.ts`); Swagger tại `/docs`.
- File upload static được serve từ `/uploads` với cơ chế fallback theo biến thể responsive (thử `_pc.webp`, `_tablet.webp`, `_mobile.webp`, `.webp`, `.jpg`, v.v. nếu path chính xác trả 404) — xem `main.ts`.
- Sau khi thay đổi `prisma/schema.prisma`, chạy `prisma:generate`. Thay đổi schema trên DB thực tế được quản lý bằng các file SQL thô trong `database/migrations/` (được nạp qua service `db-init` của Docker), **không phải** `prisma migrate`.
- Sau khi thay đổi một endpoint, kiểm tra các nơi tiêu thụ trong `apps/web`: endpoint danh sách phải giữ nguyên pagination/filter meta và mọi field mà UI list/card dùng; endpoint detail phải giữ nguyên các field nested mà UI detail dùng; DTO create/edit phải bao quát mọi field của form; endpoint admin không bao giờ được trả về password.

### Frontend (`apps/web`, Next.js App Router + TypeScript)

Hai route group:
- `src/app/(site)/` — storefront công khai. Các route tiếng Việt là chính thức (`/san-pham`, `/tin-tuc`, `/ve-chung-toi`, `/lien-he`, `/chinh-sach/[slug]`); các alias tiếng Anh (`/products`, `/news`, `/about`, `/contact`, `/policy/*`) redirect 308 sang route chính thức qua `src/middleware.ts`.
- `src/app/(admin)/admin/` — admin panel. Có quy tắc riêng (xem `apps/web/src/app/(admin)/admin/AGENTS.md`): `admin-panel.tsx` chỉ là shell ở mức route (session guard, logout, chọn view) — **không bao giờ thêm feature logic vào đây**. Mỗi feature admin có folder riêng (`products/`, `orders/`, `media/`, `news/`, `contacts/`, `users/`, `settings/`, `dashboard/`, `auth/`); code chung chỉ nằm trong `admin/common/` (`types.ts`, `api.ts`, `session.ts`, `ui.tsx`).

Các quy ước khác:
- Mặc định dùng React Server Component; chỉ thêm `use client` khi component cần state/browser API/event handler/Zustand/router navigation.
- Việc fetch data đi qua `src/lib/api.ts` (`apiGet`/`apiGetWithMeta` gọi tới `API_INTERNAL_URL` ở server-side hoặc `NEXT_PUBLIC_API_URL` ở client-side) — không tạo thêm fetch utility trùng lặp. URL media phải đi qua `mediaUrl`/`mediaVariantUrl` (các hàm này loại bỏ các origin nội bộ đã biết và viết lại hậu tố biến thể responsive).
- State cart nằm ở `src/store/cart.ts` (Zustand) — tái sử dụng thay vì thêm state cart mới.
- Dùng Tailwind cho styling; ưu tiên utility class hơn custom CSS, chỉ dùng arbitrary value khi cần khớp chính xác với template.
- Các quy tắc typography/readability (tuân thủ Google Merchant Center / UX) được áp dụng toàn repo: body text ≥16px desktop / ≥15px mobile, line-height 1.6–1.75; không bao giờ dùng `text-xs`/`text-[10-13px]` cho tiêu đề sản phẩm, giá, field/tổng tiền checkout, CTA, nhãn nav, nội dung policy hoặc mô tả/thông số sản phẩm, hay thông tin liên hệ (chỉ được dùng cho badge/nhãn giảm giá/metadata phụ); tránh dùng `text-gray-400` cho nội dung quan trọng trên nền trắng — dùng `text-gray-600/700/800`; ưu tiên `font-medium`/`font-semibold` hơn `font-bold` trừ khi là badge/brand mark/CTA mạnh. Các target kích thước cho từng component (header, product card, product detail, checkout, footer) được ghi trong `apps/web/AGENTS.md` — kiểm tra file này trước khi chỉnh sửa các component đó.
- Các control có thể click: chiều cao tối thiểu 40px trên desktop / 44px trên mobile. Dùng HTML ngữ nghĩa (`button`, `nav`, `main`, `section`, v.v.) và `alt` có ý nghĩa cho mọi ảnh.

## Data model

`apps/api/prisma/schema.prisma` là nguồn chân lý (source of truth) cho cấu trúc dữ liệu; các model: `Banner`, `Brand`, `Category`, `Contact`, `FacebookPost`, `News`, `Order`, `OrderDetail`, `Policy`, `Product`, `ProductImage`, `ProductSimilar`, `Review`, `ReviewImage`, `Slider`, `SysParam`, `User`, `UserImage`. Hầu hết các bảng dùng soft-delete (`delFlag`/`del_flag`) thay vì xóa cứng — cần filter theo field này trong các query của repository. Vai trò user: `0` = Admin, `1` = Nhân viên, `2` = Khách hàng. Các setting toàn site được đọc từ bảng `SysParam` (`sys_param`), không phải từ file env/config.
