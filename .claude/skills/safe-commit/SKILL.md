# Safe Commit

Dựa trên `.claude/rules/02-git-safety.md`.

## Cách thực hiện

1. Chạy `git status` và `git branch --show-current`.
2. Nếu branch hiện tại là `main`/`master`/`production`: **dừng lại**, báo cho người dùng, đề xuất tạo branch mới thay vì commit trực tiếp (hook `block-main-master-commit.sh` cũng sẽ chặn ở tầng command).
3. Xem `git diff`/`git status` để xác nhận chỉ có file liên quan đến task được stage — không dính `.env`, `node_modules`, `dist/`, `.next/`, file bị `.gitignore`.
4. Chạy lint/format phù hợp với phần vừa sửa (`npm run lint` ở root, hoặc `npm run format` trong `apps/web` nếu sửa frontend).
5. Không có test runner trong project — bỏ qua bước test, ghi rõ trong báo cáo.
6. Soạn commit message mô tả "why", **không** chứa các cụm `code by claude`, `generated by claude`, `AI generated`, `Co-authored-by: Claude` trừ khi người dùng yêu cầu rõ ràng.
7. Chỉ thực hiện `git commit` sau khi các bước trên pass. Nếu có bước fail (lint lỗi, branch sai), dừng lại và báo cáo, không commit.
8. Không tự `git push` trừ khi được yêu cầu rõ ràng.
